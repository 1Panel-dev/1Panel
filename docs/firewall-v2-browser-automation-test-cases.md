# 防火墙 V2 浏览器自动化测试用例

## 1. 文档说明

- 测试分支：refactor/firewall-v2-foundation
- 对比基线：dev-v2
- 开发环境默认入口：http://localhost:4004/hosts/firewall/rules
- 当前共享测试环境入口：http://172.16.10.111:9999/hosts/firewall/setting
- 测试范围：
  - 主机防火墙统一规则管理
  - 外部规则识别、描述展示、搜索与纳管
  - iptables、nftables、firewalld、UFW 后端
  - 端口转发
  - Docker 容器端口防护
  - 防火墙后端设置、禁 Ping、端口白名单
  - 权限、异常恢复、持久化和安全回归
- 暂不包含：历史数据迁移验证
- 本文档包含当前工作区修复：
  - 主机防火墙规则搜索即时过滤
  - 端口转发 interface 为星号时按“全部网卡”处理

优先级定义：

- P0：主流程阻断级，必须全部通过
- P1：重要功能和异常边界，发布前应通过
- P2：兼容性、低概率异常和增强验证

## 2. 测试环境矩阵

| 环境 | 系统/后端 | 必测范围 |
|---|---|---|
| E1 | Ubuntu + UFW | 主机规则、UFW Application、IPv4/IPv6 |
| E2 | Rocky/AlmaLinux + firewalld 0.7 或更高版本 | zone、service、rich rule、优先级 |
| E3 | iptables | 三条 1Panel 链、外部规则、端口转发、Docker 防护 |
| E4 | 原生 nftables | 主机规则、端口转发、Docker 防护、全部网卡回归 |
| E5 | Docker IPv4 | 容器端口防护 |
| E6 | Docker IPv4 + IPv6 | 双栈容器端口防护 |
| E7 | 非管理员用户 | 权限和只读状态 |

建议使用隔离虚拟机执行初始化、绑定、停止防火墙、禁 Ping 和访问阻断测试，避免中断开发机 SSH。

### 2.1 当前共享测试环境

当前浏览器自动化回归使用以下环境。节点名称和地址以 1Panel 主机列表中的实际显示为准，不得把后端类型推断到其他节点。

| 节点 | 入口/标识 | 防火墙后端 | 必测范围 |
|---|---|---|---|
| 主节点 | `172.16.10.111:9999` | iptables | 三条 1Panel 链、外部规则、端口转发、Docker 防护、设置页 |
| 110 节点 | 主机列表中的 110 节点 | UFW | 主机规则、UFW Application、IPv4/IPv6、启动/停止/重启 |
| 98 节点 | 主机列表中的 98 节点 | firewalld | zone、service、rich rule、优先级、runtime/permanent |
| 47.120 节点 | 主机列表中的 47.120 节点 | nftables | 主机规则、端口转发、Docker 防护、全部网卡回归 |

执行跨后端用例时，必须先在 1Panel 页面切换到对应节点，再执行该后端的页面操作和终端断言。测试报告必须记录实际节点、后端名称和后端版本。

### 2.2 浏览器自动化执行约束

1. 统一使用当前已登录的 Chrome 浏览器和现有 1Panel 会话执行页面自动化，不在同一轮测试中切换到应用内浏览器或其他浏览器实现。
2. 主测试标签页只操作 1Panel 防火墙页面；需要执行系统命令时，必须在 Chrome 中另开一个 1Panel Web 终端标签页。
3. 所有远端防火墙命令均通过对应节点的 Web 终端执行。不得使用本地 shell 直接修改远端防火墙状态。
4. 本地 `curl`、`ping` 或 shell 的网络结果只能用于辅助诊断，不能作为共享测试环境是否可访问或用例是否通过的唯一依据；浏览器与本地命令可能使用不同的 VPN、代理或网络上下文。
5. 页面断言以主测试标签页的可见状态、请求响应、Toast/Alert/Confirm 和控制台日志为准；系统规则断言以对应节点 Web 终端的命令输出为准。
6. 切换节点后，必须重新确认当前节点名称、实际后端和后端状态，避免把规则写入错误节点或错误后端。
7. 初始化、绑定、解绑、停止/重启防火墙、禁 Ping、访问阻断、清空规则等高影响操作前，必须确认当前节点和恢复路径；操作后立即验证面板仍可访问。
8. 自动化控制连接失败不等于测试环境不可访问。应先确认 Chrome 标签页能否正常刷新，再将问题分类为“浏览器控制阻塞”或“环境不可达”。
9. 每个用例必须标记为 `PASS`、`FAIL`、`BLOCKED` 或 `SKIPPED`；未实际执行的用例不得记为通过。
10. 完整回归结束前必须清理测试数据并复核四个节点，存在残留时不得标记为“完整测试完成”。

每条用例结束后清理：

- 面板创建规则
- 外部测试规则
- 端口转发规则
- Docker 防护策略
- 测试容器
- 临时导入和导出文件

## 4. 通用自动化断言

每次新增、编辑、删除、导入、切换或同步操作至少检查：

1. 操作按钮 loading 状态能够正常结束。
2. 成功操作出现成功提示，失败操作不能出现伪成功提示。
3. 列表总数、当前行内容和分页状态正确。
4. 刷新页面后结果保持一致。
5. 对应系统防火墙规则与页面状态一致。
6. 页面无未处理异常、白屏或持续 loading。
7. 浏览器控制台无本次操作产生的新错误。
8. 测试产生的数据可以完整清理。

建议保存以下测试产物：

- 操作前后截图
- 请求 URL、请求体和响应状态
- Toast、Alert、Confirm 文本
- 操作前后列表总数
- 系统防火墙命令输出
- 数据清理结果

| COMPAT-08 | P1 | 不支持的协议和原生规则只读展示 |
| COMPAT-09 | P1 | IPv6 不可用时 IPv4 不被连带阻塞 |
| COMPAT-10 | P1 | 后端命令失败时不留下半条管理记录 |

## 19. 建议自动化执行顺序

1. 导航、状态和权限。
2. 设置页只读状态。

8. 主机规则导入导出。

## 20. 自动化通过标准
